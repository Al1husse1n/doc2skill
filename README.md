# doc2skill

doc2skill converts documentation (local markdown or a docs URL) into an agent skill — a compact `SKILL.md` that another agent can load to actually use the tool being documented.

## Installation

`doc2skill` is not published on PyPI yet. Install it as an editable package from source:

```bash
git clone https://github.com/Al1husse1n/doc2skill.git
cd doc2skill
pip install -e .
```

## Environment

Configure Gemini access via environment variables (no `.env` files are loaded automatically):

- `GEMINI_API_KEY` — Google Gemini API key (required for frontmatter synthesis and corpus condensation)
- `DOC2SKILL_LLM_MODEL` — Gemini model name (optional; defaults to `gemini-2.5-flash`)
- `DOC2SKILL_API_KEY` — optional shared API key; when set, `POST /api/build` requires an `X-API-Key` header
- `SUPABASE_URL` & `SUPABASE_SERVICE_ROLE_KEY` — optional Supabase credentials for persistent remote skill caching (falls back to local disk cache when unset)

### Token costs

A typical docs site build costs $0.01–$0.10 on `gemini-2.5-flash` depending on docs size. Built-in budget guards enforce `--max-tokens` (default `50000`) before invoking the LLM.

## Usage

Build a skill from a local markdown directory:

```bash
doc2skill build ./docs --output ./output
```

Build a skill from a documentation URL (discovers `sitemap.xml` when present, up to `--max-pages` 100 by default):

```bash
doc2skill build https://docs.example.com/ --output ./output
```

Launch the local web UI (`http://127.0.0.1:8000`) with live Server-Sent Events progress streaming and `SKILL.md` download:

```bash
doc2skill serve
```

Run `doc2skill build --help` or `doc2skill serve --help` for flags (`--max-tokens`, `--max-pages`, `--max-context-tokens`, `--no-cache`, `--no-condense`, `--no-llm`).

## What it does / What it doesn't do

### What it does
- **Single-pass LLM condensation**: turns ingested pages into structured `SKILL.md` sections (`API surface`, `Common workflows`, `Gotchas`, `Reference`, `Source`).
- **Context truncation + budget guard**: drops deeply-nested tail pages first when a corpus exceeds `--max-context-tokens`, then checks estimated token cost against `--max-tokens` before calling Gemini.
- **Persistent + local cache**: checks Supabase (`skill_cache`) when configured and falls back to the local disk cache, avoiding repeated crawls and LLM charges for identical inputs (bypass with `--no-cache` / `no_cache=true`).
- **SSE web UI**: streams ingest, truncation, budget, LLM progress, and final skill download, with optional `DOC2SKILL_API_KEY` protection and per-IP rate limiting (5 requests/minute on `POST /api/build`).

### What it doesn't do (yet)
- **Hierarchical condensation**: corpora larger than `--max-context-tokens` are truncated, not map-reduced across multiple LLM passes.
- **Runtime API fact-checking**: identifier validation checks extracted tokens against source docs (with `--strict` fail mode), not live execution or upstream source introspection.
- **Distinguish inference from hallucination**: if the LLM infers a correct-but-not-in-source identifier (e.g., a `DEFAULT_TIMEOUT` constant that's real in the API but not spelled out in the docs), it's classified as `source_divergent`, not `unverified`. `--strict` only fails on `unverified`.
- **Multi-user accounts or distributed rate limiting**: authentication uses a single shared `DOC2SKILL_API_KEY`, and rate limiting is tracked in memory per server instance.

## Deployment & Persistent Cache (Render + Supabase)

Free-tier containers spin down and lose local disk state. Configuring Supabase keeps cached skills persistent across restarts so repeat builds return immediately before crawling or calling Gemini.

1. Create the `skill_cache` table in your Supabase project's SQL Editor:

```sql
create table if not exists public.skill_cache (
  cache_key text primary key,
  source text not null,
  max_tokens integer not null,
  model text not null,
  skill_md text not null,
  created_at timestamptz not null default now()
);
```

2. Deploy on Render using the included `render.yaml` Blueprint (free Docker web service exposing port `8000` with health check `/api/health`).
3. Configure environment variables in Render:
   - `DOC2SKILL_API_KEY` — auto-generated by `render.yaml`; enter it in the **API key** input next to **Build skill** in the web UI (sent as `X-API-Key`).
   - `GEMINI_API_KEY` — your Google Gemini API key.
   - `SUPABASE_URL` — your Supabase project URL (`https://<project-ref>.supabase.co`).
   - `SUPABASE_SERVICE_ROLE_KEY` — your Supabase `service_role` key (server-side only; bypasses RLS if enabled on `skill_cache`).

If `SUPABASE_URL` or `SUPABASE_SERVICE_ROLE_KEY` is omitted, `doc2skill` logs no error and falls back cleanly to local disk caching.
